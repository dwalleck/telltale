# Confluence report page

One page per sprint, generated by the tool and published through the Confluence REST API, so nobody maintains it by hand. Audience: leadership who get overwhelmed by data, plus anyone willing to drill in.

A design sketch exists on a claude.ai design canvas; all numbers on it are sample data. This file is the version of record for its layout.

## Top of page: the whole story on one screen

1. **Summary panel** (Info panel macro): one sentence stating the result, one sentence stating the recommended next step.
2. **Three headline tiles**: senior review rounds per PR; "85% of 3-point issues finish within N days"; issues delivered per seat per sprint. Each shows current value, baseline, and the change.
3. **Quality guardrails** row with status lozenges (Status macro): HOLDING or WATCH per guardrail (revert rate, reopened issues, median PR size).
4. **One trend chart**: review rounds per PR by sprint, structured vs. ad hoc, with the start of the evaluation marked. Rendered as a PNG by the tool (simpler and identical every sprint) or the Chart macro.
5. **Side by side**: "What hasn't improved yet" (stated plainly) and "Next step" (the ask, sized to the evidence).

## Below: details in collapsed sections (Expand macros)

Each detail table highlights the one row that supports the headline.

- **Flow: where time goes** — median business days per status, baseline / structured / ad hoc.
- **Review load** — review rounds, not-fixed threads, time to first review, time to re-review, median PR size. Notes that every group has 5+ people.
- **Seat value and credits** — issues per seat, ticket-branch sessions with no merged result, non-ticket session share, Pro credit use.
- **Model tier: replay benchmark and case studies** — the four-condition benchmark table; links to the two case study pages.
- **Method and definitions** — business days, median/P85, own-baseline comparison, pseudonymization and minimum group size, date the success criteria were sent.

Footer: refresh cadence and a contact.
